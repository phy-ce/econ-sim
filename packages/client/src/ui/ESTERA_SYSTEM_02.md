# Estera System 02 — 게임 디자인 시스템 설계

작성: 2026-11-07. 상태: 새로운 설계 제안. 현재 게임에 적용된 규칙이나 검증 완료된 시안이 아니다.

## 1. 무엇을 만드는가

에스테라의 경제를 관찰하고, 원인을 찾고, 대안을 비교하고, 명령한 뒤 결과를 확인하는 PC 게임 인터페이스다. 대상은 게임 전체이며 홍보 사이트나 일반 업무용 대시보드가 아니다. Victoria 3와는 별개의 게임으로 설계한다.

사용자는 긴 시간 여러 창의 숫자를 비교한다. 초보자에게 필요한 것은 더 큰 빈 공간이 아니라 읽는 순서와 명확한 진입점이다. 숙련자에게 필요한 것은 안정된 열, 보존되는 선택, 빠른 왕복이다.

새 시스템의 단위는 기존 버튼·카드 목록이 아니라 **경제적 판단 한 번**이다. 예를 들어 ‘벨마르 항에 섬유 농장을 더 지을까’에는 지역, 현재 생산, 부족 원료, 일손, 비용, 소유, 공사 상태가 필요하다. 이 정보를 어떤 순서와 관계로 보여 줄지부터 결정한다.

이번 설계의 기본 방향은 **촘촘한 비교 행 + 분명한 조작 영역 + 지도와 게임 그림의 정체성**이다. 큰 수치 카드, 카드 안의 카드, 모든 구역을 접는 방식은 기본형에서 제외한다.

### 우선 적용할 원칙

1. 정확한 뜻: 범위·기간·단위가 다른 숫자는 같은 열에서 비교하지 않는다.
2. 관계가 보이는 밀도: 같은 열은 같은 질문에 답하고, 가까운 정보는 같은 판단에 속한다.
3. 움직이지 않는 조작: 값이 갱신돼도 버튼·선택 행·스크롤·입력은 제자리에 남는다.
4. 차분한 표면: 색은 상태와 식별을, 그림은 대상을, 간격은 관계를 드러낸다.
5. 깊어져도 돌아올 수 있음: 한 단계 상세와 독립 이력으로 탐색하며 중첩 툴팁은 쓰지 않는다.

충돌 시 1→3→2→5→4 순으로 판단한다. 읽을 수 없는 고밀도, 명령을 밀어내는 장식, 실적처럼 보이는 미리보기는 탈락이다.

## 2. 플레이 과제에서 정보 구조로

| 플레이 과제 | 최초 화면에 필요한 정보 | 더 깊게 여는 내용 | 최종 행동 |
|---|---|---|---|
| 부족한 상품 찾기 | 범위, 상품, 가격, 공급/수요, 충족 상태 | 생산처·소비처, 가격 추이 | 관련 건설·상품 상세 열기 |
| 건물을 더 지을지 판단 | 현재 규모, 실제 가동, 손익, 일손, 증설 비용 | 방식 비교, 원료 공급, 개별 건물 | 증설/신규 건설 |
| 적자 원인 찾기 | 매출·원료·임금·손익을 같은 기준으로 | 실제 가동의 요인, 판매율, 임금표 | 방식·가동·임금 조정 |
| 재정 조정 | 현금/한도, 기간별 수지, 항목별 금액 | 세금·복지·임금의 대상과 조건 | 단계·법 변경 |
| 주민 상태 이해 | 지역·계층·인원·생활수준·소득 | 소득 원천·소유·고용 관계 | 관련 기관과 정책 탐색 |
| 연구 선택 | 현재 연구·비용·선행 조건·해금 | 실제 기술 관계와 방식 비교 | 연구 선택 |
| 결과 확인 | 명령 상태, 완료 사건, 같은 기간의 전후 값 | 추이·대상 상세 | 유지/수정/다음 행동 |

정보 깊이는 세 층이다. **전체 상황 → 비교 목록 → 대상 상세**. 설명·정확값은 툴팁의 별도 책임이며 네 번째 탐색층으로 만들지 않는다. 숫자 근거에 객체 탐색이 필요하면 명시적인 상세 링크를 둔다.

## 3. 화면과 창의 계약

기준은 1920×1028 CSS viewport. 현재의 여러 창 동시 열기·드래그·창별 이력·닫기 후 포커스 복원을 유지한다. 새 설계 때문에 좌우 고정 자리나 두 창 제한을 부활시키지 않는다.

| 표면 | 책임 | 금지 |
|---|---|---|
| 지도 | 위치·연결·지역 상태, 객체 선택 | 표의 모든 숫자를 지도 라벨에 중복 |
| 상단 | 현재 세계·기간·시간 제어·핵심 상태 | 새 칩을 무제한 추가 |
| 주 창 | 같은 종류의 대상을 비교·검색·선택 | 큰 대표 그림, 한 항목당 큰 카드 |
| 상세 창 | 한 대상의 운영·원인·행동 | 서로 다른 대상의 상세를 끝없이 세로 연결 |
| 단일 툴팁 | 정확값·정의·제약 이유 | 버튼, 또 다른 툴팁, 탐색 트리 |
| 명령 결과 | 대상·수락/거절·진행 상태 | 성공 여부를 색만으로 표현 |

주 창 420×560, 상세 520×640을 우선 검증 틀로 사용한다. 이 크기를 모든 내용에 강제할지 바꿀지는 실측 뒤 별도 결정한다. 지도 가시성을 위해 창 자체를 무작정 키우는 것으로 밀도 문제를 해결하지 않는다.

창의 기본 골격은 `제목/이력 → 범위·필터 → 내용 → 명령 영역`이다. 명령이 없는 창에는 빈 하단 영역이 없다. 제목은 객체명, 보조 문맥은 지역·소유·기간이며 같은 말을 본문에서 반복하지 않는다.

## 4. 다섯 가지 밀도

| 밀도 | 설계 규칙 | 건설 창에서의 판정 |
|---|---|---|
| 시각 | 같은 숫자의 기준선을 맞춘다. 묶음 안 간격과 묶음 사이 간격을 구별한다. | 토지 여유·일손·실제 가동을 한 줄짜리 지표 행으로 비교 |
| 정보 | 반복 제목·장식 테두리는 줄이고, 분모·기간·미제공은 남긴다. | 각 숫자의 `/일` 반복 대신 열 제목에 하루 기준을 한 번 표시 |
| 디자인 | 크기·색·선의 변화마다 역할이 있어야 한다. | 상품 그림은 상품 식별, 채움은 비율, 굵은 글씨는 결과에만 사용 |
| 시간 | 첫 판단을 위해 여러 구역을 열지 않아도 된다. | 손익·가동·비용·건설 버튼은 처음부터 노출, 개별 건물만 펼침 |
| 가치 | 판단과 무관한 정보는 상세로 옮긴다. | ‘지을까’ 판단 중 소유주별 전체 배당 표는 별도 상세 |

밀도는 `비교`와 `조작` 두 문맥으로 둔다. 비교 표는 28px 단일행, 그림이 있는 비교 행은 36px, 조작 행은 32px를 초기 후보로 쓴다. 사용자에게 전역 ‘촘촘함’ 슬라이더를 먼저 노출하지 않는다. 실험 화면에서만 후보를 비교한다.

420×560 주 창의 예산: 제목 32 + 범위/검색 64 + 열 머리 28 + 내부 여백 16 = 140px. 남은 420px에는 28px 행 15개 또는 36px 행 11개가 들어간다. 하단 명령이 40px이면 각각 13개/10개다. 이는 산술 예산이며 실측 결과가 아니다. 두 줄 라벨이 필요한 행을 자르거나 28px에 억지로 넣지 않는다.

## 5. 새로운 시각 언어

방향 이름은 **에스테라 — 지도와 기록**. 시대감은 지도·건물 그림·문장·창 제목에 집중하고, 숫자 영역은 균질한 표면과 선명한 글자로 만든다. 내부에 양피지 얼룩·광택·금색 테두리를 겹치지 않는다.

### 색 역할과 초기 후보

다음 값은 새 설계의 출발 후보다. 전체 부품·모든 조합의 대비를 검증한 값으로 주장하지 않는다. 데이터 식별색은 이 표와 별도다.

| 의미 토큰 | 밝음 | 어두움 | 용도 |
|---|---|---|---|
| surface.canvas | #E8E6DF | #171C21 | 시스템 바탕 |
| surface.panel | #F8F7F2 | #222930 | 읽는 표면 |
| surface.subtle | #ECECE5 | #2C353E | 머리·선택 보조 |
| text.primary | #222D34 | #EDF0EA | 주요 라벨·값 |
| text.secondary | #525F66 | #B7C2C9 | 단위·보조값 |
| border.control | #7A858A | #788892 | 필수 조작 경계 |
| border.separator | #C3CAC8 | #43505A | 비필수 구분선 |
| action.primary | #245A80 | #A7D2F0 | 실행·선택 |
| action.onPrimary | #FFFFFF | #142B3D | 실행 버튼의 글자 |
| result.positive | #28613F | #A8D7B4 | 이익/흑자 + 부호 |
| result.negative | #9B352E | #FFB3A6 | 손실/부족 + 부호/라벨 |
| status.warning | #855409 | #EFC47D | 주의 아이콘·라벨 |
| focus.ring | #6549AB | #D4BEFF | 키보드 위치, 선택과 독립 |

왕실·저택·금융가의 소유 식별은 아이콘+이름+작은 띠로 표시한다. 큰 초록색 면 전체에 흰 글씨를 놓아 비율을 읽게 하지 않는다. 비율은 인접 구간, 금액은 수치로 분리한다. 왕국색은 sim의 식별자를 보존하되 글자색으로 직접 사용하지 않고 표지나 지도 채움으로 쓴다. 계층색은 표·차트·지도에서 공통 식별 토큰을 쓴다.

주의색과 왕실색이 비슷해도 형태·자리·아이콘으로 구별한다. 조작색은 결과색과 분리한다. 색의 원색 자체를 모든 의미에서 서로 다르게 만드는 것은 목표가 아니다.

### 글자·숫자·그림

| 역할 | 초기 크기/행간 | 규칙 |
|---|---|---|
| 창 제목 | 16/22px | 기존 명조 계열 후보, 객체명 한 번 |
| 구역 제목·열 머리 | 13/18px | 고딕, 중간 굵기, 과도한 대문자 금지 |
| 기본 라벨·표 값 | 14/20px | Noto Sans KR 기반, 한/영 동일 역할 |
| 단위·보조 | 12/16px | 필수 판단을 이 크기로 밀어 넣지 않음 |
| 핵심 결과 | 18/24px | 상세의 주요 결과 최대 1~2개, KPI 카드 남용 금지 |
| 상품·계층 그림 | 24/32px | 목록/상세, 라벨과 기준선 정렬 |
| 대상 대표 그림 | 40px | 상세 머리에 한 번, 모든 행에서 반복 금지 |
| 조작 아이콘 | 16/20px | 실제 클릭 영역 최소 28px, 텍스트 버튼은 32px 후보 |

숫자는 tabular-nums, 우측 정렬, 최대 소수 둘째 자리. 같은 열의 단위와 소수 정밀도를 통일한다. 줄임 표기와 정확값을 공용 함수로 관리한다. 0은 0, 결측은 —, 잠금은 잠금 아이콘으로 구별한다. 음수 부호는 `−`이며 이익률이 −100% 미만이면 `< −100%`로 표시한다. 극단값 툴팁도 짧게 포맷한다.

기본 간격은 4/8/12/16px. 항목 내부 4, 같은 묶음 8, 구역 경계 12, 창 안쪽 12를 초기 후보로 둔다. 모든 항목에 16px 패딩을 주지 않는다. 수치 표는 좌우 정렬을 위해 셀 padding을 따로 정의한다. 모서리는 일반 조작 3px, 창 4px 후보. 카드형 구역은 기본적으로 만들지 않는다.

## 6. 컴포넌트 계층

| 층 | 구성요소 | 책임 |
|---|---|---|
| 0 의미 | EntityRef, Metric, Period, Quantity, CommandState | 대상·값·단위·시점·상태 계약 |
| 1 기초 표현 | Text, Number, Unit, Icon, Rule, Surface, Focus | 읽기·정렬·대비·입력 위치 |
| 2 단일 조작 | Action, EntityLink, Toggle, Field, Stepper, Tabs | 실행/이동/선택/입력의 의미 구분 |
| 3 경제 정보 | MetricRow, ResourceRow, RatioMeter, OwnershipStrip, BalanceRows, WorkforceRow | 게임 수치와 관계의 공통 표현 |
| 4 작업 묶음 | ProductionLedger, BuildingSummary, MethodCompare, ConstructionOrder, BudgetControl, EventEntry | 경제 판단과 명령 한 번 |
| 5 화면 틀 | ComparisonWindow, EntityWindow, TimelineWindow, RelationView | 목록·상세·시간·관계의 탐색 |

범용 Card를 모든 정보의 기본 용기로 삼지 않는다. Section은 제목과 행 묶음이며 기본 배경·테두리는 없다. 구역 구분선은 인접한 정보의 관계가 바뀔 때만 둔다.

### 핵심 부품의 구체 계약

| 부품 | 구조 | 값/상태 | 상호작용 |
|---|---|---|---|
| MetricRow | 라벨 · 값 · 단위 · 상세 진입점 | 결측·현재·기준·예상 구분 | 정확값은 툴팁, 분해는 명시적인 상세 |
| ResourceRow | 그림+상품 / 수량 / 금액 / 충족 | 입력은 비용·충족, 출력은 매출·판매 | 상품명으로 상품 상세 |
| RatioMeter | 라벨·실제 비율 + 얇은 막대 | 막대만 0~100% 제한, 과부족 숫자 보존 | 장식 클릭 금지, 링크면 명시 |
| OwnershipStrip | 인접 구간 + 아래 기관명·몫 | 지분·레벨·인원을 혼합하지 않음 | 기관별 소유 상세 |
| BalanceRows | 매출, 원료, 임금, 세금, 결과 | 같은 기간, 실제 API가 제공하는 항목 | 수치 분해가 없으면 추정 행을 만들지 않음 |
| ProductionLedger | 투입 행군 / 산출 행군 / 요약 | 실제·기준 레시피·예상 상태를 분리 | 기본은 실제, 방식 비교는 별도 진입 |
| ConstructionOrder | 수량, 비용, 공기, 조건, 실행 | 가능·조건 미충족·전송 중·접수·거절 | 최소 입력과 최종 실행 위치 유지 |
| MethodCompare | 방식별 열, 항목별 행 | 현재 표시·비교 차이·잠금 | 방식 선택과 적용을 구별 |

## 7. 첫 적용: 섬유 농장 · 벨마르 항

행군 대신 큰 화살표나 중앙 건물 그림을 놓지 않는다. 투입과 산출의 방향은 제목과 열 역할로 충분히 드러낸다. 원료 3종·산출 2종이면 같은 열 구조로 행만 늘어난다. 스크롤은 정보 본문 한 곳에서만 하고 건설 명령 영역은 창 아래에 유지한다. 고정 영역은 공간을 실제로 차지하며 마지막 행을 덮지 않는다.

공급/수요 전체 표, 소유주별 배당, 개별 건물 조작은 링크로 상세를 연다. 첫 판단에 필요한 손익·실제 가동·일손은 접지 않는다. 멈춘 건물은 상태 라벨과 실제 가동 0을 표시하고 기준 레시피와 구별한다. 소유 기관·행정·학교·건축사무소는 생산 부품을 강제하지 않고 해당 서비스량·수지·인력 부품을 조합한다.

수량 입력 후 비용·조건이 같은 자리에서 바뀐다. 건설 명령은 현재 선택 지역·유형·방식·수량을 포함한다. 접수 성공 시 대기열에 반영되고 거절 시 같은 영역에 짧은 사유 라벨을 둔다. 예상 생산을 확정 실적으로 그리지 않는다.

## 8. 다른 화면으로 확장

| 화면 | 새 구성 | 유지할 의미 |
|---|---|---|
| 시세 | 범위 한 줄 + 상품 비교 표 + 선택 상품 상세 | 지역/왕국/세계 분리, 공급÷수요, 잠긴 상품 |
| 지역 | 개요 지표 행 + 인구/건물 비교 표 | 토지·교육·임금·소유 링크, 지역 독립 이력 |
| 국가 | 예산 항목 행 + 단계 조작, 법은 비교 목록 | 세금/복지/임금의 실제 조건, 잠금과 읽기 전용 |
| 연구 | 현재 연구 한 묶음 + 기술 목록 + 관계도 | 선행 조건·해금·진행과 선택의 구분 |
| 통계·소식 | 동일 기간 차트 + 사건 목록 | 축·범례·기간·결측, 읽음과 정지 사유 |

재정은 생산 손익과 기간이 다를 수 있으므로 같은 BalanceRows라도 기간을 필수로 받는다. 인구의 1인 임금과 전체 임금도 같은 숫자 부품만 공유하며 같은 열 의미로 합치지 않는다.

## 9. 실시간 동작·접근성

- 선택·호버·포커스·실행 가능·잠금은 각각 별도 상태다. 선택된 행에도 키보드 포커스가 보인다.
- 실제 명령 버튼은 채움+동사, 객체 이동은 이름+진입 단서, 읽기 전용 값은 버튼처럼 그리지 않는다.
- 단일 툴팁은 포인터와 키보드 포커스로 열고 Escape로 닫는다. 복잡한 내용과 조작은 상세창으로 보낸다.
- 매 업데이트마다 숫자나 행을 튀게 하는 애니메이션은 없다. 정렬은 조작 중 고정하고 명시적 정렬 변경 또는 작업 종료 시 적용한다. 비교 대상 ID를 보존한다.
- 입력·드래그의 로컬 상태는 세계 스냅샷과 분리한다. 닫힌 창은 렌더하지 않으며 무거운 표·차트는 표시 중인 데이터만 갱신한다. 선택자·memo는 trace 근거가 있는 곳에 적용한다.
- 갱신을 미루면 미뤄진 세계 시점을 숨기지 않는다. 창 머리의 작은 시점 표지로 현재/지연을 구분하고, 입력과 포커스를 유지한 채 최신 결과를 받는다.
- 핵심 글자 대비 4.5:1, 필수 비문자 조작 단서 3:1을 검증 목표로 한다. 28/32px 조작 크기는 PC 후보이며 터치 적합성이나 접근성 인증으로 주장하지 않는다.
- 움직임 줄이기 설정을 존중하고 명령 결과는 애니메이션 없이도 알 수 있게 한다. 게임 데이터 갱신을 모든 숫자에 live announcement하지 않는다.

## 10. 하나의 구현 출처

새 체계는 `의미 토큰 → 기초 표현 → 경제 부품 → 화면 조합` 순으로 의존한다. 기존 ui/tokens.css·components.css·runtime.css는 이행 대상이지 새 설계의 정의가 아니다.

1. 초기 구현은 독립 scope에서 검증한다. 기존 게임 CSS 마지막에 계속 덮어쓰지 않는다.
2. 의미 토큰에는 역할 이름만 쓰고 화면 파일에서 새 색·행 높이를 직접 정하지 않는다.
3. Number/Metric의 단위·반올림·극단값 표기를 공용 함수와 타입으로 묶는다.
4. 게임과 디자인 시스템 탐색 화면이 같은 컴포넌트를 import한다. 목업 전용 복제 부품은 만들지 않는다.
5. 화면별 차이는 밀도/종류 variant로 표현한다. `.construction-detail .x` 같은 연쇄 보정은 예외로 기록한다.
6. 테마·lang·density는 공통 경계에서 전달한다. 의미색·아이콘 크기를 바꾸면 실제 사용 화면도 함께 바뀌어야 한다.
7. 이전 셀렉터 제거는 참조 검색과 화면 검증 뒤에만 한다. sim과 프로토콜은 변경하지 않는다.

카탈로그의 순서는 **기초 표현 → 조작 → 경제 정보 → 작업 묶음 → 실제 창**이다. ‘몇 개 장/결정/검토 중’ 같은 요약 카드는 넣지 않는다. 아이콘 24/32/40, 행 28/32/36, 여백 4/8/12, 한/영·낮/밤·극단값 전환을 같은 데이터로 비교하는 실험 도구를 둔다. 미리보기는 실제 부품의 문서이자 회귀 표본이다.

## 11. 실행 계획과 완료 기준

| 단계 | 산출물 | 통과 조건 |
|---|---|---|
| 0 안전한 기준점 | 미완료 2-95·2-96 분리 완료, 현재 상태 기록 | 타입·클라이언트 시험, 명시 파일 커밋 |
| 1 기초 표현 | 새 의미 토큰·타이포·숫자·아이콘·상태 표본 | KO/EN, 낮/밤, 긴 이름·극단값·포커스 판독 |
| 2 핵심 경제 부품 | ResourceRow·ProductionLedger·MetricRow·OwnershipStrip·ConstructionOrder | 실제·기준·정지·부족·결측의 구분, 데이터 계약 시험 |
| 3 건설 수직 적용 | 목록→상세→방식→건설→대기열 | 기능 회귀 없음, 첫 화면에서 판단값·명령 확인 |
| 4 비교 화면 확대 | 시세→지역/인구→국가→연구→통계 | 공통 부품 사용, 화면별 숫자 의미 보존 |
| 5 이전 규칙 정리 | 중복 CSS·어댑터·미사용 규칙 정리 | 대표 화면 회귀 캡처, 토큰 수정 전파 확인 |

각 단계는 typecheck·client vitest·1920×1028 헤드리스 확인 후 명시 파일만 영어 커밋, push하지 않는다. 디자인 문서만 바뀐 단계에는 실행 검증을 했다고 적지 않는다.

대표 데이터 세트: 생산 정상 / 원료 부족 / 일손 부족 / 정지 / 원료 3종 / 혼합 산출 / 매출 0 / 극단적 적자 / 긴 영어 이름 / 여러 소유주 / 조건 미충족 / 공사 진행. sim 값이 없는 미리보기는 ‘미제공’ 상태로 두고 요청을 기록한다.

성능은 같은 세이브·배속·열린 창·조작 스크립트로 전후 비교한다. 1배속과 10배속에서 각 30초, 건설·인구·통계 동시 열기와 드래그/스크롤을 포함한다. 메인 스레드 50ms 초과 작업의 횟수·최대시간, React commit·레이아웃·역직렬화 시간을 분리한다. 드래그 p95 프레임 간격 20ms 이내, 조작 반응 p95 100ms 이내를 초기 목표로 두되 측정 전 달성했다고 쓰지 않는다.

사용성 검토는 ‘가동이 낮은 이유 찾기’, ‘두 방식 비교’, ‘섬유 농장 한 단계 증설’, ‘명령 뒤 같은 대상 복귀’ 네 과제로 한다. 시간·오선택·불필요한 열기 횟수를 기록한다. 예쁜 화면인지와 별도로 완료 가능성을 판정한다.

## 12. 적용 전에 확인할 큰 선택

이번 문서는 아래의 추천 방향까지 구체화한 설계안이다. 사용자 미응답을 확정으로 기록하지 않는다. 작은 간격·토큰 조정마다 별도 승인을 요구하지 않는다.

1. **정체성:** 밝은 중립 기록면+지도/게임 그림을 추천. 기존 양피지 전체 도색을 유지하면 시대감은 강하지만 표면 간 구분이 약해진다. 예: 섬유 농장 안쪽은 평평한 기록면, 건물 그림은 머리에만 둔다.
2. **생산 표현:** 상품별 투입/산출 행군을 추천. 중앙 건물 그림과 연결 화살표는 없애고 두 묶음의 같은 열을 비교한다. 원료가 여러 개일수록 차이가 커진다.
3. **숫자 서체:** 본문 고딕의 tabular 숫자를 추천. 픽셀 숫자를 정체성으로 남기려면 날짜·시대 표지처럼 읽기 부담이 낮은 곳으로 한정하는 안을 검토한다.
4. **기본 노출:** 가동·일손·손익·명령은 펼쳐 두고, 개별 기관/건물 목록은 상세로 보내는 안을 추천. 접힌 제목만 많이 보이는 창을 피한다.
