# 화면 설계: 지금 화면과 규칙

경제 쪽 `docs/DESIGN.md`처럼, 지금 화면이 어떻게 생겼고 어떤 규칙을 따르는지 한 장에 모은 문서다. 지금 유효한 것만 적는다.
- 기준 코드: main `1aca9ad` (클라이언트는 `31ca0d5`와 같음, 2026-11-01). 문서와 코드가 다르면 코드를 적고 차이는 10장 "어긋남"에 모은다.
- 우선순위: 사용자 최신 요청 > 이 문서 > 날짜별 기록 파일(13장). 할 일은 [UI_CHANGES](UI_CHANGES.md), 구현·검증 상태는 [UI_STATUS](UI_STATUS.md), 끝난 변경은 [UI_DONE](UI_DONE.md).
- 이 문서를 고치는 사람: UI/UX 담당(Claude). 화면 작업자는 규칙이 코드와 달라지면 UI_STATUS에 적고, 담당이 여기에 옮긴다.

## 1. 화면 기준
- 대상 화면은 1920×1080 하나다. 다른 해상도·크기 조절 대응은 목표가 아니다 (사용자 결정).
- 시험 기준은 브라우저 CSS viewport 1920×1028 (화면 외곽 1920×1080에서 브라우저 틀을 뺀 값). 모니터 해상도와 CSS viewport를 혼동하지 않는다.
- 창이 움직이는 범위는 viewport에서 상단 바와 아래 도크(52px, `strategy.css:87`)를 뺀 workspace이고, 코드는 이를 실측한다 (`WindowWorkspace.tsx:20` ResizeObserver, 첫 값 1920×998 `:12`).
- 정보는 왼쪽·오른쪽 가장자리의 좁고 밀도 높은 창에 두고 가운데 지도가 보이게 한다 (사용자 기준). 글씨를 일괄 줄이기보다 장부형 표·서브윈도우·툴팁으로 밀도를 높인다.

### 2.3 서브윈도우 (`views/DetailWindow.tsx`)
- 주 창 안 내용을 덮지 않는 비모달 창. `document.body` portal, 제목 드래그·크기 조절·Esc 닫기·닫을 때 연 버튼으로 포커스 복원.
- workspace 경계 안으로 위치·최대 크기를 맞춘다 (ResizeObserver).
- 창마다 자기 탐색 이력(뒤로/앞으로)을 가진다 (`DetailWindow.tsx:18~20`, 2026-11-01).

## 3. 창 규칙
- 여러 주 창을 동시에 열고 자유롭게 옮긴다. 누른 창이 앞으로 온다. 좌우 고정 자리·최대 두 창 규칙은 2026-10-28에 폐기했다.
- 주 창 크기는 420×560 CSS px 상한, workspace가 작으면 줄인다 (`WindowWorkspace.tsx:16`). 사용자가 크기를 바꾸지 않는다. 처음 자리는 계단식 (`:19`, x 24 + 76i, y 16 + 36i), 옮긴 자리는 그 세션 동안 기억한다 (저장하지 않음).
- 이동: 제목 드래그 (requestAnimationFrame마다 transform 한 번, 놓을 때 한 번 저장, `windowDrag.ts`), 제목에 포커스 후 방향키 20px.
- 주 창마다 탐색 이력이 따로다 (`NavigationHistory.tsx`, `useNavigationState`). 한 창 안에서 링크를 따라가도 다른 창은 바뀌지 않는다. 다른 종류의 창으로 가는 링크는 그 창을 열고 앞으로 가져온다 (`GameWindow.tsx:23`).
- 상세는 서브윈도우와 툴팁으로 연다. 주 창을 길게 늘리지 않는다.

## 4. 시각 규칙
### 4.1 테마와 색
- 색은 `:root` 토큰으로 쓰고 다크 모드는 `:root[data-theme="dark"]`에서 다시 정한다 (`styles.css:2~56`). 테마는 메뉴에서 고르고 `localStorage`에 남는다 (기본 낮, `App.tsx:38~40`).
- 낮: 양피지 바탕 `--paper #f3ead8`, 종이 `--sheet`, 먹 `--ink`, 강조 `--accent`, 금 `--gold`. 밤은 같은 이름의 어두운 값. 밤에는 그림 뒤에 양피지 받침을 깐다 (`styles.css:83~84`).
- 색의 뜻: `--good`/`.pos` 초록 = 이익·흑자, `--bad`/`.neg` 빨강 = 손실·부족, `--gold` = 주의·유보 자산. 이익 막대는 초록/빨강/회색과 +/−를 같이 쓴다 (색만으로 뜻을 전하지 않는다).
- 계층 색 토큰: `--c-peasant`, `--c-unskilled`, `--c-skilled`, `--c-expert`, `--c-capitalist`, `--c-aristocrat`, `--c-gentry` (`styles.css:19~24`, `strategy.css:74`). 도넛·차트·표·막대가 같은 색을 쓴다.
- 손익 폭포 색: `--wf-rev` 매출, `--wf-raw` 원료, `--wf-wage` 임금.
- 왕국 색은 sim이 준다 (`world.ts` `color`: 에스테라 `#e11d48`, 벨로니아 `#3b82f6`, 카르텐 `#10b981` 등). 지도 왕국 레이어와 소유 배지 띠에 쓴다.

### 4.2 소유 구분
- 소유권 바 (`OwnershipBar.tsx`): 높이 24px, 몫마다 아이콘 + 색. 왕실 = 왕관, 저택 = 집, 금융가 = 기관, 없음 = 선. 누르면 소유주 표 서브윈도우.
- 소유 배지 (`OwnerBadge.tsx`): 왕관(왕실)/돈주머니(민간), 왕국 색 띠, 플레이어 별.
- 화면에 "XX 민간" 회사 이름을 쓰지 않고 "민간"(또는 저택·금융가)으로 쓴다 (UI_CHANGES 2-35).
- 저택·금융가에는 가동률·원료 충족을 보이지 않고 자리 충원·금고·하루 수입을 보인다 (`OwnerSummary.tsx`).

### 4.3 막대·바·아이콘·글꼴
- 같은 모양의 24px 아이콘 바를 쓴다: 소유권 바, 유보 자산 바(`ReserveBar.tsx`, 동전 + 금색 채움, 숫자는 바 위 전체 폭), 건물 요약 바(`BuildingMetricBars.tsx`, 충원 = 파란 채움, 이익 = 색 + 부호, 이익에는 가짜 충전율을 그리지 않는다). 누르면 정확한 값의 서브윈도우.
- 작은 막대는 `ui.tsx` `Bar` (tone pos/neg/gold/in/out). 채움은 0~100%로 자르고 숫자는 실제 값을 쓴다.
- 그림: 게임 소품은 생성 아이콘 아틀라스 (`Sprite`, `Sprite64`, 480px 셀·최소 48px 여백, 상품·건물·계층·지역·기상·사건 72개, `npm run assets:check`가 sim id 대응을 검사). 조작 단추는 `lucide-react` 아이콘.
- 지도: 생성 해안 바탕 + 공유 SVG 경계, 레이어 셋 (왕국 / 부 / 생활수준, `RegionMap.tsx:37`), 확대 100~300%, 이름표는 확대해도 같은 크기.
- 글꼴: 제목 `--serif` (Gowun Batang), 본문 `--sans` (Noto Sans KR), 숫자 칸 `--pixel` (Silkscreen, `.pxnum`). 숫자는 `tabular-nums`.

## 5. 숫자 표기 (`format.ts`, `NumericValue.tsx`)
- 플레이어에게 보이는 값은 소수 둘째 자리까지 (CLAUDE.md). 저장값과 sim 계산값은 반올림하지 않는다 (2026-10-22 사용자).
- 1,000 이상은 k/M/B/T 한 자리 (`compact`), 1,000 미만은 형식에 따라 정수·한 자리·두 자리 (`int`/`one`/`two`). 돈은 `ƒ`와 부호 `−`/`+` (`money`, `signedMoney`). 비율은 정수 % (`pct`).
- 줄인 숫자는 `NumericValue`로 그려 툴팁·`aria-label`에 정확한 값을 둔다. 값이 없거나 정의되지 않으면 "—" (0으로 꾸미지 않는다).
- 단위는 라벨에 둔다: "/ 일", "/ 주", "/ 주·L"(레벨당). 사람·소득처럼 집단 값은 기본이 1인당이다 (ui-ux 규칙, 10장 어긋남 참조).
- 플레이어가 읽는 숫자는 흔들리지 않게 이동평균·주 단위 값을 쓴다. 날짜는 1년 = 360일, 한 달 = 30일 (`dateParts`).

## 6. 문자열 (한/영)
- 모든 화면 문자열은 한국어·영어 둘 다 있다. 기준은 `strings.ts`의 `KO`·`EN`(`Dict` 타입이 짝을 강제)과 `useT()`, 언어는 `useLang()` (`i18n.ts`). 사전 이름(상품·건물·지역·직종·기술)은 `i18n.ts`의 `goodName`·`buildingName` 등과 sim `i18n`을 쓴다.
- 영어 긴 이름은 말줄임 + 전체 이름 툴팁. 숫자 열은 줄바꿈하지 않는다.

## 7. 설명 문구 금지, 툴팁
- 화면에는 라벨·숫자·막대·칩·아이콘만 둔다. 원리 설명은 README와 규칙 사전에 쓴다 (CLAUDE.md).
- 툴팁은 된다: `data-help` 속성 하나로 통일, 280ms 뒤 최상위 층에 뜬다 (`TooltipLayer.tsx`), 키보드 포커스로도 뜬다. 정확한 값, 항목 정의, 계산 근거를 툴팁에 둔다.
- 아이콘만 있는 단추에는 이름 툴팁(`title`/`aria-label`)을 단다.
- 소식·토스트의 글은 sim이 만든 사건 문장이다 (설명 문구가 아니다).

## 8. 사전 연결
- 규칙 사전은 별도 사이트다 (`packages/encyclopedia`, 공개 주소 `https://phy-ce.github.io/econ-sim/encyclopedia/#<항목 id>`). 지금 화면은 정책 창 법 이름 옆 책 아이콘에서 새 탭으로 연다 (`PolicyPanel.tsx:27`, 항목 `tax-laws`·`invest-law`·`welfare`).
- 사전 숫자는 sim 코드 상수를 읽는다. 화면이 규칙 숫자를 옮겨 적지 않는다.

## 9. 시간과 알림
- 1배속 = 하루 24초 (`BASE_TPS = 25/24` 틱/초, `App.tsx:33`). 단축키 Space 재생/정지, 1~5 속도.
- 내 회사의 위험(danger) 소식이 새로 생기면 멈춘다 (메뉴에서 끈다, `useGame.ts:69~85`). 내 회사 소식은 모두, 왕국 전체 소식은 위험만 토스트로 띄우고, 나머지는 소식함에만 둔다.
- 소식 링크는 건물·지역·회사·창으로 간다 (`eventDestination.ts`).

## 10. 어긋남 (문서·규칙과 코드가 다른 곳, 2026-11-01)
1. **집단 값 기본 1인당**: 규칙은 1인당이 기본인데 `BuildingPops.tsx:20` 집단/1인당 전환의 기본값이 집단(`false`)이다.
2. **소유권 바 색이 토큰이 아니다**: `OwnershipBar.tsx:9`가 색을 박아 둔다 (왕실 `#a64240`, 저택 `#87601c`, 금융가 `#246f96`, 없음 `#687078`). 다크 모드에서 바뀌지 않고, 같은 왕실을 `workspace.css:160` 토큰 `--royal-owner`(`#a04438`, 밤 `#e98879`)와 다른 빨강으로 그린다.
3. **문자열이 strings.ts 밖에 있다**: 컴포넌트 안 `ko?'…':'…'` 삼항이 16개 파일에 약 220곳 (`views/`, `App.tsx`). 둘 다 있으니 언어는 맞지만 `Dict`가 짝을 검사하지 못한다.
4. **화면 문장**: `BuildingPops.tsx:26` 빈 목록에 문장 "이 건물에 속한 팝이 없습니다." (라벨·"—"로 바꿀 것).
5. **폐기된 고정 자리 코드가 남아 있다**: `windowGeometry.ts`(`slotRect`·`placeWindows`, 440px 좌우 자리)와 `windowLayout.ts`는 화면에서 쓰지 않고 시험(`test/windowGeometry.test.ts`, `test/windowLayout.test.ts`, `test/uiRefresh.test.ts`)만 쓴다. `WindowId`에도 안 쓰는 `'overview'`·`'industry'`가 남아 있다 (`WindowWorkspace.tsx:7`).
6. **왕실 임금 슬라이더**: sim이 왕실 생산 건물 임금 명령을 거절하는데 재정 창이 슬라이더를 그린다 (`CompanyPanel.tsx:459`, UI_CHANGES 2-69).
7. **브라우저 확인**: 2026-10-28 이후 추가분 대부분이 화면 미검증이다 (UI_STATUS). 이 문서의 화면 서술은 코드 기준이고 눈으로 확인한 것이 아니다.
8. **사전은 새 탭**: 오버홀 09가 정한 게임 안 사전 창(단위 G)은 아직 없다. 지금은 정책 창 한 곳에서만 새 탭으로 연다.
9. **옛 기록 수치**: 날짜별 기록의 창 크기(460×560, 440×982, 480×620)와 "좌우 두 자리"는 지금 코드와 다르다 (기록으로만 둔다, 13장).

## 11. 앞으로 바뀔 것
오버홀 화면 설계 [09_UI_UX](overhaul/09_UI_UX.md)가 다음 화면을 정한다: 상단 바 사람 칩, 몫의 장부 창, 숫자를 눌러 여는 분해 창, 정책·재정을 합친 국가 창(예산/법), 건설 창 입구, "~까지 ▸" 진행과 정지 사유, 처방 추적 핀, 게임 안 사전 창, 기록 창. 단위(A~N, P)와 순서는 09 7.2, 지금 넘긴 단위는 UI_CHANGES 0장 (K 2-70, C 2-71, H 2-73, J 2-74). 단위가 반영되면 이 문서의 해당 절을 고친다.

## 12. 검증 방법
- 루트 `npm run typecheck` (sim + client + 사전). 클라이언트 시험은 범위를 좁혀 `npx vitest run packages/client/test` (루트에서 넓게 돌리면 `.tmp` 작업 사본까지 수집한다).
- `npm run build` (client): 지도 이웃(7지역·9쌍)과 아이콘 목록 검사(`assets:check`) 포함.
- 개발 서버: `cd packages/client && npx vite --port 5199`.
- 눈 확인: 1920×1028 viewport, 한국어 낮 + 영어 밤, 가로 넘침 없음, 콘솔 오류 없음. 브라우저를 열 수 없는 작업자는 "화면 미검증"으로 적고 UI_CHANGES 0장 "검증" 줄에 남긴다. 예전 검증 결과를 새 변경에 이어 쓰지 않는다.
