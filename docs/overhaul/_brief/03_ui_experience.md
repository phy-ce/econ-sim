## 3. 첫 30분 (코드로 재구성한 장면 단위)

가정: 처음 접속, 저장 없음, 한국어, 1배속 유지. 1배속에서 1년 = 345.6초(5.76분)이고 30분은 약 5.2년이다. 4배속이면 같은 30분이 약 20.8년이다 (App.tsx:33-34 계산).

### 장면 1. 0:00 부팅 (약 1초)
- 보이는 것: 문장 아이콘 하나, 접근성 라벨 "불러오는 중" (App.tsx:115).
- 일어나는 일: 워커가 `createWorld(Date.now() % 100000)` 로 무작위 시드 세계를 만든다 (sim.worker.ts:11). 저장이 있으면 곧바로 불러온다 (useGame.ts:99-101).
- 피드백: 없음. 시드 선택·시나리오 선택·이름 입력 화면이 **없다**. [사실]

### 장면 2. 0:05 첫 화면 (정지 상태)
- 보이는 것: 상단 바(날짜 "왕국력 1년 1월 1일 00시", 칩 3개), 전체 화면 지도(7개 지역, 3색 왕국 구분, ★ 내 건물 수), 하단 도크 7개 버튼. 창은 없다.
- 시간은 **정지**다 (워커 `ticksPerSecond = 0`, sim.worker.ts:13). 사용자가 Space 나 속도 버튼을 눌러야 간다.
- 소식함에는 "대륙의 시장이 열렸습니다." 한 줄뿐이다 (world.ts:186). 읽지 않은 수 배지는 info 라 0이다 (App.tsx:136).
- 칩: 국고는 "정부 건물 운영비 × 26주" 로 시작한다 (TUNE.startTreasuryWeeks 26, data.ts:548). 지난주 손익은 첫 주가 끝나기 전이라 0 근처로 추정 (확인 못 함). 징수율은 시작 계산값 (world.ts:303-307).
- [해석] 무엇을 해야 하는지 알려주는 것이 화면에 하나도 없다. 아이콘만 있는 도크와 "★" 표시, 지도의 레이어 토글이 전부다.

### 장면 3. 0:30 지도 클릭
- 행동: 지도에서 지역 하나를 누른다 → `selectRegion` 이 지역 창을 연다 (App.tsx:120).
- 보이는 것: 420×560 창. 탭 3개(개요·인구·건물). 개요는 장부 형태다: 생활수준·인구·1인당 부·노동자 부·실업·교육·소작 비율과 막대, "지역 건물 전체 보기 N" 버튼 (RegionPanel.tsx:85-100).
- 항목을 누르면 별도 서브윈도우가 열린다 (인구 구성 도넛, 토지 소유, 교육). 소유권 바(왕실 적색/저택 황갈/금융가 청색)는 눌러서 소유주 표를 연다 (UI_WINDOWS_2026-10-28.md:16).
- [해석] 한 지역 안에서 "이 지역에 문제가 있나"를 알려주는 단일 신호(경고 배지)는 없다. 숫자를 읽고 판단해야 한다. 지도 레이어(부/생활수준)가 유일한 전체 비교다.

### 장면 4. 1:30 시간을 흘려 보낸다
- 행동: Space 또는 "1×".
- 보이는 것: 날짜 시계가 시간 단위로 움직이고(`hour` 메시지, sim.worker.ts), 칩 숫자가 갱신된다. 세계 전체 스냅샷은 틱이 바뀔 때 최소 300ms 간격으로만 온다 (FULL_MIN_MS, sim.worker.ts:28).
- 하루가 0.96초라 첫 주(7일)는 약 6.7초다. 주 단위 이벤트(연구 적립·알림·예산)는 약 7초마다 온다.
- [해석] 정지에서 시작하므로 사용자가 천천히 읽을 시간은 있지만, 읽을 거리의 우선순위가 없다.

### 장면 5. 2:00 건물을 지으려 한다 (지역 → 건물 탭)
- 행동: 내 왕국 지역 선택 → 건물 탭 → "새 건물" 서브윈도우. 지도 클릭 → 창 → 탭 → 버튼 → 서브윈도우, 4단계.
- 보이는 것 (BuildList, CompanyPanel.tsx:487-528): "건설 가능 N / M", 필터(전체/가능/조건 미충족), 검색, 정렬, 카드 그리드. 카드마다 건물 그림, 예상 하루 이익, 투자 회수 일수. 카드를 열면 생산 방식 목록(일꾼, 원료→산출, 방식별 하루 이익 예상), 비용·기간·회수, 버튼 "<지역>에 짓기"와 "+5".
- 막히는 사유가 툴팁 한 줄로 나온다: 외국 영토 · 땅 부족 · 기술 필요 · 동시 공사 40개 · 건축사무소 없음 (CompanyPanel.tsx:477-485).
- 시작 시 왕실은 건축사무소 20레벨(하루 약 40 포인트)을 갖는다 (DESIGN 시작 상태). 건설 비용은 포인트이고 기간은 카드에 일수로 보인다. [사실]
- 피드백: 눌러서 명령을 보내면 즉시 적용되고(틱을 기다리지 않음, sim.worker.ts `enqueue` 주석), 실패하면 오류 토스트(`errors` → `toast(err,'error')`, useGame.ts:67). 성공은 토스트가 없다. 건설 창 대기열에 항목이 생기는 것이 확인 수단이다. [사실]
- [해석] "예상 하루 이익 +"는 있지만 그 숫자가 어디서 오는지(시세·임금·원료)를 따라가려면 시세 창·인구 창으로 옮겨야 한다. 이익 근거가 한곳에 없다.

### 장면 6. 3:30 연구 (조용히 낭비되는 지점)
- 행동: 도크 "연구".
- 보이는 것: 주간 연구 pt, 왕국 문해력, 현재 연구 "연구를 선택하세요", 가능 기술 목록, 선택 기술 상세(선행·해금 건물/방식/정책, 필요 주 수), 계통도 버튼 (ResearchPanel.tsx).
- **고른 기술이 없으면 매주 연구 포인트가 사라진다** (finance.ts:65-70 `advanceResearch`: 기술이 없으면 `r.points=0`). 게임은 정지 상태에서 시작하므로 첫 주 전에 고르면 손실이 없지만, 연구를 안 열어보고 시간을 흘리면 알림 없이 손실된다. [사실]
- 연구 포인트는 `50 + 3 × 문해력(%)` 주간, 1단계 기술 4,500 pt (README 기술 절). 문해력 30%면 약 32주(약 3.6분 1배속). [사실, README]
- [해석] 연구는 "돈이 안 드는 선택"이라 부담은 없지만, 첫 선택의 의미(무엇이 열리는가)는 툴팁/상세를 읽어야 안다. 알림 시스템에 "연구 선택 없음" 경고는 없다 (alerts.ts 전체 확인: 연구 관련 알림 없음).

### 장면 7. 5:00 재정과 정책
- 행동: 칩 "국고" 누름 → 재정 창.
- 보이는 것: 주간 예산 표(수입·지출 줄, 손잡이 묶음: 세금 수준·국영 임금·복지 수준 각 1~5 단계), 줄을 누르면 서브윈도우로 계산 내역(FinancePanel.tsx). 단계 위에 마우스를 올리면 그 단계의 예산이 미리 보인다 (`hover` 미리보기).
- 정책 창: 세법 3종(토지세·인두세·소득세), 투자법, 복지법. 전환에는 180일이 걸리고 진행 막대가 보인다. 기술이 열려야 선택 가능한 법이 있고, 조건(금융가 자산 비율)을 못 채우면 비활성화되며 사유는 툴팁이다 (PolicyPanel.tsx).
- 법 이름 옆 책 아이콘은 **외부 사이트(규칙 사전)를 새 탭으로** 연다 (`https://phy-ce.github.io/econ-sim/encyclopedia/#...`, PolicyPanel.tsx 22행 부근). 게임 안에서 사전을 여는 곳은 이것뿐이다. [사실]
- 알려진 문제: 예산 미리보기 오차 테스트가 실패 중이다 (budget.test.ts:85, 오차 0.38 > 허용 0.2, 원인 미조사. UI_STATUS.md:38). [사실]

### 장면 8. 8:00 첫 알림 (주 1회 검사라 첫 주(약 7초)부터 가능, 실제 첫 알림 시점은 시드마다 다름)
- 알림 원천: `weeklyAlerts` 가 매주 한 번 검사한다 (tick.ts:116). 종류는 아래 4장 표.
- 화면 반응: 내 회사(id 100)의 알림은 모두 토스트, 왕국 공통(`companyId null`)은 위험만 토스트 (useGame.ts:76). 위험이면 게임이 **자동 정지**한다 (useGame.ts:77-83, 기본 켜짐).
- 토스트에 지역이 있으면 "↗" 링크로 지역 창이 열린다 (App.tsx:215).
- 종을 열면 소식함이 있다: 필터(내 왕국/경고/전체), 검색, 미확인만, 정렬 3종, 날짜 구분선, 항목 → 건물·지역·상회로 바로 이동 (Notifications.tsx). [사실]
- 어떤 알림이 처음 올지는 시드마다 다르다 (확인 못 함: 이 문서에서 시뮬레이션을 돌리지 않았다). 시작 세계에서 먼저 나올 후보는 기상(계절마다 지역당 5% 확률, README), 소작농 기아(인구 5천 이상, 식량 충족 < 60%), 무임금(`unpaid`) 이다.

### 장면 9. 15:00 (약 2.6년) — 반복 루프
- 가능한 반복: 지역을 돌며 건물을 짓는다 → 건설 창에서 진행을 본다 → 연구가 끝나면 새 방식(소식 한 줄) → 방식을 바꾸거나 새 건물을 해금 → 재정 단계를 조정.
- 피드백은 거의 모두 **숫자와 막대**다. "잘하고 있는가"의 기준은 없다. 비교 기준은 통계 창의 순위 표(상회별 순자산·건물 수·지난주 손익)와 왕국별 그래프 정도다 (BottomPanel.tsx).
- 4배속으로 올리는 사용자는 이 구간에서 주 알림 다수를 놓칠 수 있다. 위험만 멈춘다. [해석]

### 장면 10. 30:00 (1배속 약 5.2년, 4배속 약 20.8년)
- 저장: 메뉴 → 저장. 성공 토스트 "저장했습니다." 실패 "저장 실패" (useGame.ts:88-95). 자동 저장은 없다. 브라우저를 닫으면 마지막 수동 저장 이후 진행분이 사라진다. [사실]
- 다음 접속: 부팅 시 저장이 있으면 **묻지 않고** 불러온다 (useGame.ts:99-101). 새 게임은 메뉴 → 확인창 → 완전 무작위 시드 (`Math.random()*1e6`, useGame.ts:136). 시드를 입력하거나 되돌아가는 방법은 없다.
- [해석] 30분 동안 "한 번의 결정이 어떤 결과를 가져왔는지"를 되짚는 화면이 없다. 소식 문장이 가장 가까운 기록이다.

## 4. 목표·피드백·알림·속도·저장의 현재 상태

### 4-1. 목표 [사실]

| 있는 것 | 없는 것 |
|---|---|
| 순위 표(순자산·건물 수·지난주 손익) | 승리·패배 조건 |
| 왕국별 GDP·1인당 GDP·인구·생활수준 등 9개 추이 | 점수·등급·업적 |
| 국고가 바닥나면 자동 국채 (한도 내) | 시나리오·과제·단계별 안내 |
| 정책 전환 조건(금융가 자산 비율 문턱) | 튜토리얼·첫 실행 안내·"다음 할 일" |
| 연구 트리 (진행 감각의 유일한 구조물) | 게임 종료/엔딩 |

- 소작농 빈곤은 착취로 만든다는 설계 제약(CLAUDE.md)이 있어, 목표를 "생활수준 N"으로 두면 정책과 충돌할 수 있다. [해석]
- 20년 단위 비교 실험 문화(CLAUDE.md, 보고서 앱)는 개발자 도구에서만 쓰이고 플레이어 화면에는 없다. [해석]

### 4-2. 피드백

| 채널 | 무엇을 | 얼마나 자주 | 한계 |
|---|---|---|---|
| 상단 칩 3개 | 순국고/한도, 지난주 손익, 징수율 | 틱마다 | 인구·생활수준·실업은 없음 |
| 토스트 | 내 회사 이벤트 전부, 공통 위험 | 이벤트 즉시, 4/8/12초 | 성공한 명령은 토스트 없음 |
| 종 + 소식함 | 이벤트 로그 (필터·검색·이동) | 주 단위 알림 위주 | 종 배지 계산이 두 곳에서 다르다 (아래) |
| 지도 레이어 | 왕국/1인당 부/생활수준 색 | 틱마다 | 4단계 색 구간 (부 4·6·9) |
| 통계 | 월별 기록 9지표, 1년/5년/전체, 왕국 비교 | 30일 기록 | 기록 2개 미만이면 "대기" |
| 건물 카드 | 가동률·충원·이익·유보자산 막대 | 틱마다 | 건물마다 열어봐야 함 |
| 명령 결과 | 오류만 토스트 | - | 성공 확인은 다른 창을 봐야 함 |

- 종 배지 불일치: 상단 배지는 `info` 제외·내 회사+공통만 센다 (App.tsx:136). 소식함 안 "미확인" 수는 `info` 를 포함하고 같은 왕국 회사를 모두 센다 (Notifications.tsx:55). "모두 읽음"은 `world.tick` 까지 모든 소식을 읽음으로 한다. [사실]
- 한 번 읽음으로 하면 이전으로 되돌릴 수 없다. 읽음 기준은 틱 하나뿐이다 (useGame.ts `lastReadTick`). 저장에는 포함되지 않는다 (필드가 hook 상태). [사실]

### 4-3. 알림 (sim 원천)

| 알림 | 종류 | 대상 | 재알림 | 코드 |
|---|---|---|---|---|
| 임금 미지급 → 노동자 이탈 | danger | 건물 소유 회사 | 4주 | alerts.ts 25-28 |
| 투입재 충족 < 50% | warn | 건물 소유 회사 | 4주 | alerts.ts 29-37 |
| 인력 < 50% | warn | 건물 소유 회사 | 4주 | alerts.ts 38-43 |
| 건축사무소 없음/멈춤 | danger / warn | 회사 | 4주 | alerts.ts 48-62 |
| 투입재 가격 > 기본가 1.6배 | warn | 회사 | 4주 | alerts.ts 64-84 |
| 기상(가뭄·홍수·산불) 새로 시작 | warn | 그 지역 왕실 | 조건 시작마다 | alerts.ts 87-96 |
| 기아(식량 < 80%/소작농 60%, 5천 명 이상) | warn / danger(<20%) | 그 지역 왕실 | 8주 | alerts.ts 98-112 |
| 연구 완료, 광맥 발견 등 | info | 회사 | - | finance.ts:75, economy.ts:219 |

- 알림 문구는 한국어·영어 쌍으로 sim 이 만든다 (`en` 필드). 클라이언트는 한국어 원문을 정규식으로 분류해 아이콘을 고른다 (Notifications.tsx kindOf: `/굶|기아|식량/` 등). 문구가 바뀌면 아이콘이 조용히 어긋난다. [사실]
- **빠진 신호 [해석]**: 연구 선택 없음, 건설 대기열 비어 있음, 국고 부족 임박(국채 자동 발행), 세금 징수율 하락, 실업 급증, 정책 전환 완료. 이들은 현재 알림으로 오지 않거나(코드 확인 범위: alerts.ts) 칩/그래프를 직접 봐야 한다. 정책 전환 완료 이벤트는 policy.ts 쪽에 있을 수 있으나 확인 못 함.

### 4-4. 속도 조절

| 항목 | 값 |
|---|---|
| 1배 | 하루 0.96초 (`BASE_TPS = 25/24` 틱/초) → 1주 6.7초, 1년 5.76분 |
| 단계 | 1×, 2×, 3×, 4×, 10× (10×는 코드 주석상 디버그용, 화면에는 그대로 노출) |
| 환산 | 4배 = 1년 86초 / 10배 = 1년 35초 (계산) |
| 20년(보고서 표준 길이) | 1배 1.9시간, 4배 29분, 10배 11.5분 (계산) |
| 조작 | 정지 버튼, 숫자 버튼, Space, 키 1~5, 하루 진행(정지 중) |
| 자동 정지 | 내 회사의 `danger` 소식이 새로 생기면 (기본 켜짐, 메뉴에서 끔) |
| 시작 상태 | 정지 |
| 화면 갱신 | 틱이 지났을 때만, 300ms 이상 간격. 시계 시(時)만 변하면 가벼운 메시지 |

- 정지 중에도 명령은 즉시 적용된다 (sim.worker.ts enqueue). 정지 상태로 건설·연구·정책을 조정하는 흐름이 가능하다. [사실]
- 키 안내 UI는 없다. 버튼 `title` 에 "1×(1)" 형태로 단축키가 보인다 (App.tsx:164). [사실]
- 도크 CSS 에 `dock-hint` 클래스가 있으나 렌더하는 코드는 찾지 못했다 (workspace.css:91, 렌더 없음). [사실]
- [해석] 5.8분/년은 20년 플레이가 2시간에 가깝다는 뜻이다. "첫 30분"은 게임 내 5년 남짓이라 정책 전환(180일)·연구(약 1~2기술)·건설 몇 건이 전부일 수 있다. 이 속도 범위에서 "결과가 보이는" 시점이 첫 30분 안에 오는지는 확인 못 함.

### 4-5. 저장·불러오기

| 항목 | 상태 | 코드 |
|---|---|---|
| 슬롯 | localStorage 키 `estera-save-v7` 하나 | useGame.ts:8 |
| 저장 | 메뉴 → 저장, 워커가 직렬화한 JSON | useGame.ts:88-95, sim.worker.ts `save` |
| 자동 저장 | 없음 | grep 일치 없음 |

| 새 게임 | 확인창 후 무작위 시드 | App.tsx:183, useGame.ts:136 |

- [해석] localStorage 단일 슬롯은 크기 한계(브라우저별 약 5MB 안팎)가 있다. 세계 JSON 크기·실제 한계 도달 시점은 측정하지 않았다 (확인 못 함). 팝 소득 원천 필드가 추가됐고(UI_WINDOWS 65-72행) 저장에 들어가므로 JSON 은 커졌을 가능성이 있다.
- 클라우드 저장·파일 내보내기·여러 슬롯은 없다. 공개 배포 목표(CLAUDE.md)에서는 빠진 기능이다. [해석]

- 지도 경계·도로·강 보정이 2026-10-30에 진행 중이다 (UI_WINDOWS_2026-10-28.md:153-158). 지도가 가장 손이 많이 간 화면 요소다.

## 7. 해석: 오버홀 토론에서 부딪힐 지점

아래는 모두 [해석]이다. 근거 줄 번호는 위 절에 있다.

| 번호 | 쟁점 | 근거 |
|---|---|---|
| U1 | **목표 부재.** 승리·패배·점수가 없어 "30분 뒤에 왜 계속하는가"에 화면이 답하지 못한다. 그러나 CLAUDE.md 가 "목표"를 정해두지 않았다 | 4-1 |
| U2 | **첫 행동 안내 없음.** 도크 7개와 지도만 있고 정지 상태로 시작한다. 지도의 기본 선택 지역이 내 땅이 아닐 수 있다 | 장면 2 |
| U3 | **연구 낭비가 조용하다.** 선택 안 하면 포인트가 사라지는데 알림이 없다 | 장면 6 |
| U4 | **건설 진입 경로가 깊다.** 지도 → 지역 창 → 건물 탭 → 새 건물 → 카드 열기 → 버튼 (5단계). 건설 창은 대기열 전용이다 | 장면 5 |
| U5 | **성공 피드백 부재.** 명령이 먹었는지는 다른 창을 열어야 안다 | 4-2 |
| U6 | **알림이 건물 단위 문제 중심이다.** 왕국 단위 위기(실업·세수·국고)는 칩/그래프를 직접 읽어야 한다 | 4-3 |
| U7 | **속도 모델.** 1배 5.8분/년은 길고, 10배는 디버그용인데 노출된다. 어느 속도에서 알림이 의미 있는지 기준이 없다 | 4-4 |
| U8 | **저장 취약.** 수동·단일 슬롯·무확인 자동 불러오기. 공개 배포에는 부족 | 4-5 |
| U9 | **사전은 밖에 있다.** 게임 안 경로는 법 이름 옆 책 아이콘뿐이다. 이를 클라이언트로 옮기는 계획은 README 에만 있다 | 5 |
| U10 | **창 구조 비용.** 자유 이동 다중 창은 구현·검증 부담이 크다(드래그 성능, 경계 보정, 창별 이력). 검증이 아직 브라우저에서 못 이뤄졌다 | 2-2, 6 |
| U11 | **상단 바가 돈 위주다.** 왕국이 사람 중심 경제라면(인구 약 500만) 인구·생활수준·실업이 항상 보이는 자리가 없다 | 2-1 |
| U12 | **인지 과부하.** 규칙 사전 94개 항목, 정책 3분야, 재정 손잡이 3개, 소유권 3종(왕실·저택·금융가)을 처음 접하는 사람이 한 화면 체계로 이해할 수 있는지 기준이 없다 | 5, 2-3 |

## 8. 확인 못 한 것

- 실제 첫 화면 스크린샷·체감 성능. (브라우저 도구 연결 오류로 기록 없음. 이 작업도 시뮬레이션·브라우저를 쓰지 않았다.)
- 시작 세계에서 첫 알림이 무엇이고 언제 오는가. 시드마다 다르다.
- 첫 주 지난주 손익 칩 값, 첫 국고 숫자 (sim 실행 필요).
- 세계 JSON 크기와 localStorage 한계에 닿는 시점.
- 정책 전환 완료 등 policy.ts/commands.ts 쪽 이벤트가 소식함에 어떻게 나오는지 (alerts.ts 밖이라 읽지 않았다).
- 영어·다크 모드의 현재 시각 품질 (UI_STATUS.md:39 가 과거 통과 기록을 승계하지 않는다고 밝혔다).
- 사용자 PC 규모(해상도·배율)별 동작. 1920×1028 이외는 문서에 검증이 없다.
